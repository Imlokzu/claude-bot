# «Клод Бот» — Virtual Bot

Віртуальне втілення Клод Бота + веб-панель керування. Поки справжнє залізо
(Raspberry Pi 3, камера, дисплей) не куплене, весь бот живе локально на macOS:
бекенд FastAPI на **http://127.0.0.1:8100**, фронтенд — статичний vanilla
JS/HTML/CSS у `static/` (без збірки і без CDN), який роздає сам бекенд.

## Запуск

```bash
cd "Virtual Bot"
./start.sh
```

Скрипт сам створить `.venv`, поставить залежності (`fastapi`, `uvicorn`,
`httpx`, `pyyaml`, `websockets`) і запустить сервер. Далі відкрийте
http://127.0.0.1:8100.

Ручний варіант:

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8100
```

## Панелі фронтенду

Фронтенд (`static/`) — це панель керування з вкладками:

- **Обличчя** — анімоване обличчя бота з поточною емоцією;
- **Чат** — розмова з ботом (кожна відповідь має емоцію);
- **Зір** — снапшот і живий MJPEG-стрім з камери (стрім береться напряму з
  `http://127.0.0.1:8000/vision/stream.mjpg`, не через 8100);
- **Памʼять** — перегляд і редагування markdown-нотаток у `brain/`;
- **Сервіси** — запуск/зупинка Vision Agent (порт 8000) і Display (порт 8001);
- **Статус** — доступність мозків і сервісів, активний режим.

## Режими мозку (за пріоритетом)

0. **Omni-роутер** — ГОЛОВНИЙ мозок: OpenAI-сумісний мультимодельний шлюз на
   `127.0.0.1:20128/v1` (`POST /chat/completions`). Модель обирається у панелі
   («Модель» у шапці чату) з кованого списку в `config.yaml` (секція `omni`);
   за замовчуванням — Claude (`claude/claude-sonnet-5`). Якщо обрана модель
   впаде швидкою помилкою (401/404/503), Omni автоматично пробує запасну модель
   (`omni.fallback_model`, «другий мозок» — `opencode-go/…`), і лише потім падає
   на наступний мозок. Ключ: env `OMNI_API_KEY` — тільки з файла `.env` (див.
   «Секрети» нижче). Ключ — секрет: він ніколи не потрапляє у відповіді API,
   статику, цей README чи вікі.

   > Список моделей містить лише провайдерів, для яких у ключа Є креденшели
   > (перевірено: працюють `claude/*` і `opencode-go/*`; `github/*`, `fireworks/*`
   > тощо повертають 404/401). Тому вживаємо прямі `claude/…` й `opencode-go/…`
   > id, а не `auto/*` (той комбо-маршрутизує і може влучати в мертві провайдери).
   > Чат має короткий таймаут (`chat.omni_timeout_s`) і запобіжник
   > (`chat.omni_backoff_s`), щоб завислий роутер не тримав кожну відповідь.
1. **OpenClaw** — gateway на `127.0.0.1:18789` (OpenAI-сумісний
   `/v1/chat/completions`). Токен: env `OPENCLAW_TOKEN` (пріоритет), інакше
   читається з `../Voice Loop/config.yaml`. Токен — секрет.
2. **Anthropic API** — прямий виклик `POST /v1/messages` через httpx (без SDK),
   модель `claude-sonnet-5`. Ключ: env `ANTHROPIC_API_KEY`.
3. **Chat2API** — локальний OpenAI-сумісний сервер на `127.0.0.1:8080/v1`
   (`POST /chat/completions`), модель за замовчуванням `Qwen3.7-Max`
   (`config.yaml`, секція `chat2api`). Авторизація зазвичай не потрібна;
   якщо задано env `CHAT2API_API_KEY` — шлеться `Authorization: Bearer`.
4. **Демо** — заготовлені українські відповіді за ключовими словами, щоб
   застосунок працював завжди, навіть без мереж і ключів.

Активний режим видно в `GET /api/status` (поле `mode`). Після першого чату
`mode` показує мозок, який РЕАЛЬНО відповів останнім (ping може «брехати»:
gateway доступний, а chatCompletions віддає 500); до першого чату — очікуваний
режим за доступністю. Усі пʼять мозків отримують той самий системний промпт
(тег емоції + топ-3 нотатки памʼяті) — він модель-агностичний.

### Вибір моделі Omni

У шапці панелі «Чат» є випадаючий список моделей. Список кований у
`config.yaml` (секція `omni.models`: `id` — як віддає роутер `/v1/models`,
`label` — підпис у UI). `GET /api/models` віддає список + поточний вибір,
`POST /api/model {"model": "<id>"}` перемикає модель (приймаються ЛИШЕ id зі
списку — довільні рядки відхиляються з `400`). Вибір діє на рівні процесу
(спільний для всіх клієнтів; скидається на типовий при перезапуску сервера).

### Емоції

Системний промпт просить модель починати відповідь тегом `[емоція:happy]`
(одна з `idle | listening | thinking | speaking | happy | sad | confused |
surprised | love | sleepy`). Бекенд парсить тег і прибирає його з тексту; якщо
тега нема — емоція вгадується евристикою за ключовими словами відповіді.

**Бот міняє емоції й сам.** Фоновий «нагляд за життям» (`vision_watcher`)
публікує емоції через SSE (`/api/events`), тож обличчя оживає без запиту:
- реакція на камеру (коли Vision онлайн): поява людини → `surprised`→`happy`
  + привітання; людина пішла → `sad`; дрімота після 10 хв тиші → `sleepy`;
- **спонтанні емоції у простої**: коли бот спокійний (немає взаємодій
  ≥`mood_calm_s`, не дрімає й не сумує), він зрідка САМ показує випадкову «живу»
  емоцію (`happy/thinking/surprised/love/listening`) на кілька секунд, потім
  повертається в `idle`. Це працює й без Vision. Налаштування — у `config.yaml`
  (`liveliness.mood_*`); `mood_duration_s: 0` повністю вимикає цю поведінку.

### Памʼять

Проста файлова памʼять — markdown-нотатки в `brain/{people,topics,logs}/`.
При кожному чаті топ-3 нотатки за збігом ключових слів запиту підмішуються
в системний промпт. Шляхи нотаток валідуються (захист від path traversal).

## Ендпоінти

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/` | Панель (роздає `static/index.html`) |
| GET | `/api/status` | `{"omni","openclaw","anthropic","chat2api","vision","display","mode"}` |
| POST | `/api/chat` | `{"message"}` → `{"reply","emotion"}` |
| GET | `/api/models` | `{"models":[{"id","label"}],"selected","default"}` — моделі Omni |
| POST | `/api/model` | `{"model":"<id>"}` → перемкнути модель Omni (лише зі списку) |
| GET | `/api/vision/snapshot` | Проксі JSON з Vision Agent; `503` якщо офлайн |
| GET | `/api/memory/list` | `{"files":[{"path","title"}]}` |
| GET | `/api/memory/file?path=...` | Вміст нотатки |
| POST | `/api/memory/save` | `{"path","content"}` — зберегти нотатку |
| GET | `/api/services` | Статуси Vision/Display |
| POST | `/api/services/{vision\|display}/start` | Запустити сервіс |
| POST | `/api/services/{vision\|display}/stop` | Зупинити сервіс (лише свій процес) |

Керування сервісами: використовується `.venv` відповідного модуля, якщо є;
повторний `start` не плодить процеси; `stop` ніколи не вбиває процес, який
запускали не ми. Логи процесів — у `service_logs/`.

## Конфігурація

`config.yaml` — порти, шляхи, базові URL і список моделей Omni, **без секретів**.

### Секрети (`.env`)

Секрети живуть лише в оточенні. Найзручніше — у файлі `.env` поряд із `config.yaml`
(формат `KEY=VALUE`, можна в лапках, інлайн-коментар « #...» відрізається); його
читає `app_config` на старті — за будь-якого способу запуску (тому `start.sh`
його НЕ сорсить, лише замикає права `chmod 600`). Реальний `export KEY=...` в
оточенні завжди має пріоритет над `.env`. Тримайте `.env` із правами `600`.

- `OMNI_API_KEY` — ключ Omni-роутера (головний мозок).
- `OPENCLAW_TOKEN` — токен OpenClaw (інакше береться з `../Voice Loop/config.yaml`).
- `ANTHROPIC_API_KEY` — ключ прямого Anthropic API.
- `CHAT2API_API_KEY` — необовʼязковий ключ локального Chat2API.

**`.env` — секрет:** не комітьте його, не додавайте у вікі/фронтенд. Ключі
ніколи не повертаються з API і не потрапляють у статику.
