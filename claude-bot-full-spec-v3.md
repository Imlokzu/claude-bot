# Клод Бот — Повна технічна специфікація проєкту

**Версія:** 3.0 (об'єднана)
**Дата:** липень 2026
**Призначення документа:** повний технічний опис DIY-проєкту персонального AI-робота на базі Raspberry Pi 3, домашнього сервера та хмарних LLM API. Документ охоплює апаратну частину, архітектуру обчислень, програмний стек та розширені інтелектуальні модулі.

---

## 1. Що це за проєкт

Клод Бот — персональний AI-компаньйон, який поєднує фізичне тіло (камера, мікрофон, динамік, екран, згодом — колеса) з мовною моделлю Claude як "особистістю" та допоміжними хмарними сервісами для швидких реакцій. Ідея виникла як розвиток концепції з відео "I Gave ChatGPT a Body" (проєкт Growbot) — розподіл на швидке "System 1" (рефлекси, рух) і повільне "System 2" (мислення, розмова, планування).

Ключова відмінність від готових асистентів (Alexa, Google Home): Клод Бот має фізичну присутність, персональну пам'ять про конкретних людей у домі, і здатен виконувати завдання, що вимагають пересування й розпізнавання ("знайди мене і нагадай").

---

## 2. Архітектура обчислень: три рівні

| Рівень | Пристрій | Затримка | Функція |
|---|---|---|---|
| Edge (реакція) | Raspberry Pi 3 | <50 мс | Сенсори, локальний UI, рефлекси уникнення перешкод |
| Fog (обробка) | Домашній сервер i5-10200 | 100-500 мс | Оркестрація, планувальник, пам'ять, легка ML-обробка |
| Cloud (мислення) | Groq / Anthropic API | 300 мс - 3 с | Vision-аналіз, розмова, генерація рішень |

Принцип розподілу: чим частіше й швидше потрібна реакція — тим ближче до заліза вона виконується. Годинник, що чекає на будильник, не повинен залежати від доступності хмарного API в момент спрацювання.

## 4. Програмний стек

| Шар | Технологія | Причина вибору |
|---|---|---|
| ОС | Raspberry Pi OS 64-bit (Bookworm) | Офіційна підтримка камери через libcamera |
| Захоплення відео | picamera2 | Актуальна заміна deprecated picamera |
| Аудіо | ALSA + sounddevice | Стандарт для USB audio |
| UI дисплея | Kivy (ScreenManager + SlideTransition) | Свайп-навігація "з коробки" |
| Backend сервера | FastAPI + uvicorn | Асинхронність, легка інтеграція з зовнішніми API |
| LLM SDK | anthropic, groq (офіційні Python SDK) | Пряма підтримка провайдерів |
| Планувальник | APScheduler | Незалежний від LLM-виклику годинник |
| Векторний пошук пам'яті | ChromaDB / sqlite-vec | Легкі, локальні, без хмарної залежності |
| Face recognition | face_recognition (dlib) / InsightFace | Розпізнавання конкретних людей, не лише детекція |
| Локальний STT (рекомендовано) | Whisper (base/small) на i5 | Знижує залежність від мережі й вартість хмарних викликів |

## 5. Розподіл ролей між LLM-провайдерами

| Провайдер / модель | Роль | Причина |
|---|---|---|
| Claude (Anthropic API) | Розмова, характер, розуміння намірів, tool use | Найкраща якість розмови й слідування інструкціям |
| Groq — qwen3.6-27b (vision) | Опис сцени з камери в реальному часі | Дуже низька латентність, дешево |
| Groq — легка текстова модель | Короткі миттєві репліки-реакції | Швидкість важливіша за глибину |
| Локальний Whisper (i5) | Розпізнавання мовлення (STT) | Без затримки мережі, без оплати за кожен запит |

Важливо: vision-лінійка Groq історично змінювалась кілька разів за рік — назву моделі варто тримати в конфігурації, не хардкодити в коді.

## 6. Розширені інтелектуальні модулі

### 6.1 Агентні можливості (Tool Use)
Claude API підтримує виклик функцій — модель визначає намір користувача і повертає структурований виклик, який виконує сервер.

**Перший набір інструментів:**
- `set_alarm` — будильник (виконує APScheduler на сервері, не Claude)
- `set_reminder` — нагадування, з опційною прив'язкою до конкретної людини (розділ 6.3)
- `play_music` — відтворення через yt-dlp/Spotify API → аудіо на RPi
- `web_search` — пошук інформації, переказ голосом
- `find_person` — фізичний пошук людини по квартирі (розділ 6.4)

**Ключовий принцип:** Claude — шар розуміння наміру, а не виконавець у реальному часі. Планувальник на сервері працює незалежно від доступності Claude API в момент спрацювання будильника чи нагадування.

**Канал сповіщень:** Telegram Bot API — безкоштовний, миттєвий, без відкритих портів (long polling). Використовується, коли завдання не вдалось виконати ("не знайшов вас удома — ось нагадування тут").

### 6.2 Персональна пам'ять (RAG, "Obsidian-мозок")
Замість передачі повної історії розмов у кожен запит — структурована база markdown-нотаток з семантичним пошуком релевантного контексту.

**Структура:**
```
brain/
  people/<ім'я>.md     — факти, уподобання, важливі дати про людину
  topics/<тема>.md     — довготривалі факти про побут, план квартири
  logs/<дата>.md       — сирі щоденні записи до консолідації
```

**Життєвий цикл:**
1. Запис — Claude після розмови визначає, що варто зберегти
2. Пошук — семантичний пошук топ 3-5 релевантних нотаток перед новим запитом
3. Dream cycle — нічна фонова консолідація: прибирання дублікатів, узагальнення

**Місткість:** 32GB SD-картка — величезний запас для тексту; обмежувач не обсяг, а якість консолідації.

### 6.3 Розпізнавання конкретних людей (Face Recognition)
Відрізняється від простої детекції обличчя (для UI "очі дивляться на людину"): відповідає на питання "чиє це обличчя", а не "чи є тут обличчя".

- Детекція (легка) — локально на RPi3
- Розпізнавання-ембединги (важче) — на сервері i5, лише для кадрів з виявленим обличчям
- Потрібна початкова "реєстрація" — кілька фото на кожну людину
- Обмеження: точність залежить від освітлення й кута; потрібна політика приватності — що можна переказувати незнайомій людині, а що ні

### 6.4 Навігація (без лідара)
Обраний підхід — reactive navigation замість повного SLAM, як компроміс складність/вартість/достатність для квартири.

| Рівень | Технологія | Функція |
|---|---|---|
| Уникнення перешкод (реальний час) | HC-SR04 + локальна логіка | Стоп/розворот без мережевої затримки |
| Класифікація перешкод | YOLOv8n (nano) на сервері | "Що саме" заважає |
| Оцінка глибини (опц.) | MiDaS small / Depth Anything V2 | Без лідара, монокулярно |
| Топологічна навігація | Візуальні маркери по кімнатах (QR/кольори) | Заміна метричної карти |

**Алгоритм пошуку людини:** обхід кімнат за маркерами → сканування в кожній → детекція обличчя → розпізнавання на сервері → знайшов (дія) / обійшов усе без результату (сповіщення в Telegram).

## 7. Ключові технічні ризики

| Ризик | Мітигація |
|---|---|
| Недостатнє живлення RPi3 при пікових навантаженнях | Повербанк ≥2.5A; моніторинг `vcgencmd get_throttled` |
| Deprecation vision-моделей на Groq | Назва моделі в конфігурації, не в коді |
| Мережева затримка розмови | Локальний VAD і буферизація UI, щоб не блокувати інтерфейс |
| Точність face recognition в реальних умовах | Кілька еталонних фото, толерантність до кількох невдалих спроб |
| Складність повного SLAM без лідара | Свідома відмова — топологічна навігація замість метричної карти |

## 8. Дорожня карта реалізації

**Фаза 0 — Софт-прототип без заліза (можна вже зараз)**
"Розумна колонка" на i5 з наявним мікрофоном/динаміком — тестування розмовної логіки, tool use, пам'яті.

**Фаза 1 — Сенсорне ядро**
Камера, мікрофон, динамік, дисплей на RPi3; зв'язок із сервером; голосова розмова з Claude; Groq vision-коментування.

**Фаза 2 — Мобільність**
Шасі 4WD, мотори, дальномір; монтаж готового "тіла" з Фази 1 на шасі.

**Фаза 3 — Агент і пам'ять** (не залежить від готовності заліза, можна паралельно з Фазою 0-1)
Tool use (будильник/нагадування/пошук), Telegram-сповіщення, RAG-пам'ять, dream cycle.

**Фаза 4 — Просторова свідомість** (вимагає готових Фаз 1-2)
Face recognition, reactive navigation, топологічні маркери, повний цикл find_person.

## 10. Навіщо цей проєкт (підсумок мотивації)

Проєкт задумано не як заміну готовим комерційним рішенням (розумні колонки, роботи-пилососи), а як:
- Навчальний досвід у побудові AI-агентів з фізичним втіленням
- Персональний компаньйон з довготривалою пам'яттю про конкретних людей у домі
- Платформа, що росте поетапно — кожна фаза самостійно корисна й завершена, навіть якщо наступні фази не будуть реалізовані
