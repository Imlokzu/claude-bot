# «Клод Бот» — Virtual Bot

Віртуальне втілення Клод Бота + веб-панель керування. Поки справжнє залізо
(Raspberry Pi 3, камера, дисплей) не куплене, весь бот живе локально на macOS:
бекенд FastAPI на **http://127.0.0.1:8100**, фронтенд — статичний vanilla
JS/HTML/CSS у `static/` (без збірки і без CDN), який роздає сам бекенд.

## Запуск

```bash
cd "Virtual Bot"
./start.sh
```

Скрипт сам створить `.venv`, поставить залежності (`fastapi`, `uvicorn`,
`httpx`, `pyyaml`, `websockets`) і запустить сервер. Далі відкрийте
http://127.0.0.1:8100.

Ручний варіант:

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8100
```

## Панелі фронтенду

Фронтенд (`static/`) — це панель керування з вкладками:

- **Обличчя** — анімоване обличчя бота з поточною емоцією;
- **Чат** — розмова з ботом (кожна відповідь має емоцію);
- **Зір** — снапшот і живий MJPEG-стрім з камери (стрім береться напряму з
  `http://127.0.0.1:8000/vision/stream.mjpg`, не через 8100);
- **Памʼять** — перегляд і редагування markdown-нотаток у `brain/`;
- **Сервіси** — запуск/зупинка Vision Agent (порт 8000) і Display (порт 8001);
- **Статус** — доступність мозків і сервісів, активний режим.

## Режими мозку (за пріоритетом)

0. **Omni-роутер** — ГОЛОВНИЙ мозок: OpenAI-сумісний мультимодельний шлюз на
   `127.0.0.1:20128/v1` (`POST /chat/completions`). Модель обирається у панелі
   («Модель» у шапці чату) з кованого списку в `config.yaml` (секція `omni`);
   за замовчуванням — Claude (`claude/claude-sonnet-5`). Якщо обрана модель
   впаде швидкою помилкою (401/404/503), Omni автоматично пробує запасну модель
   (`omni.fallback_model`, «другий мозок» — `opencode-go/…`), і лише потім падає
   на наступний мозок. Ключ: env `OMNI_API_KEY` — тільки з файла `.env` (див.
   «Секрети» нижче). Ключ — секрет: він ніколи не потрапляє у відповіді API,
   статику, цей README чи вікі.

   > Список моделей містить прямі id провайдерів, які налаштовані в Omni. Regolo
   > додається саме в конфігурацію Omni: Virtual Bot не має окремого Regolo LLM
   > клієнта й передає роутеру лише вибраний model id. Вживаємо прямі `claude/…`,
   > `opencode-go/…` або підтверджені `regolo/…` id, а не `auto/*` (той
   > комбо-маршрутизує і може влучати в мертві провайдери).
   > Чат має короткий таймаут (`chat.omni_timeout_s`) і запобіжник
   > (`chat.omni_backoff_s`), щоб завислий роутер не тримав кожну відповідь.
1. **OpenClaw** — gateway на `127.0.0.1:18789` (OpenAI-сумісний
   `/v1/chat/completions`). Токен: env `OPENCLAW_TOKEN` (пріоритет), інакше
   читається з `../Voice Loop/config.yaml`. Токен — секрет.
2. **Anthropic API** — прямий виклик `POST /v1/messages` через httpx (без SDK).
   Base URL конфігурується (`anthropic.base_url`): зараз тут **SotaModel**
   (www.sotamodel.net) — сторонній Anthropic-сумісний Claude-шлюз із моделями
   `claude-opus-5` / `claude-opus-5-max` / `claude-opus-5-xhigh`. Ключ: env
   `ANTHROPIC_API_KEY` (це ключ шлюзу, НЕ офіційного Anthropic). Поки на
   акаунті SotaModel нуль балансу, кожен запит відповідає INSUFFICIENT_BALANCE
   і ланцюг просто йде далі; після поповнення мозок оживає без змін коду.
3. **Chat2API** — локальний OpenAI-сумісний сервер на `127.0.0.1:8080/v1`
   (`POST /chat/completions`), модель за замовчуванням `Qwen3.7-Max`
   (`config.yaml`, секція `chat2api`). Авторизація зазвичай не потрібна;
   якщо задано env `CHAT2API_API_KEY` — шлеться `Authorization: Bearer`.
4. **Демо** — заготовлені українські відповіді за ключовими словами, щоб
   застосунок працював завжди, навіть без мереж і ключів.

Активний режим видно в `GET /api/status` (поле `mode`). Після першого чату
`mode` показує мозок, який РЕАЛЬНО відповів останнім (ping може «брехати»:
gateway доступний, а chatCompletions віддає 500); до першого чату — очікуваний
режим за доступністю. Усі пʼять мозків отримують той самий системний промпт
(тег емоції + топ-3 нотатки памʼяті) — він модель-агностичний.

### Вибір моделі Omni

У шапці панелі «Чат» є випадаючий список моделей. Список кований у
`config.yaml` (секція `omni.models`: `id` — як віддає роутер `/v1/models`,
`label` — підпис у UI). `GET /api/models` віддає список + поточний вибір,
`POST /api/model {"model": "<id>"}` перемикає модель (приймаються ЛИШЕ id зі
списку — довільні рядки відхиляються з `400`). Вибір діє на рівні процесу
(спільний для всіх клієнтів; скидається на типовий при перезапуску сервера).

### Голос

- **ASR:** `/api/asr` передає аудіо браузера до Regolo `faster-whisper-large-v3`.
  Потрібен локальний секрет `REGOLO_ASR_API_KEY`; маршрут вимагає такого самого
  Clerk-входу, як чат, і приймає не більше 10 MiB аудіо за запит. Якщо Regolo
  недоступний, бекенд повертає `503`, а панель використовує свій браузерний
  резервний режим. Ніякого серверного fallback у цей тестовий період немає.
- **Живі проміжні результати:** `/api/asr/partial` — чорновий текст, поки
  людина ЩЕ говорить. Екран пише аудіо шматками по 1.2с і шле НАКОПИЧЕНЕ
  (перший шматок несе заголовки webm, тож окремий шматок не декодується),
  а показує те, що встигло розпізнатись. Модель окрема й менша
  (`asr.partial_model`, типово `small`): тут важлива швидкість, а точність
  добере остаточний `/api/asr`. Вимикається `asr.partials: false`.
- **Швидкість локального ASR** (заміряно на M2 Pro, фраза 1.1с):
  було 5.7с → стало 2.5с остаточне і 0.7с проміжне. Дало три речі:
  `cpu_threads` за кількістю ядер, `float32` замість `int8` на arm64
  (у ctranslate2 там немає швидких int8-ядер) і прогрів моделі на старті
  (функція `warm()` існувала, але її ніхто не викликав, тож ПЕРШЕ
  розпізнавання платило ще ~5с за завантаження). Для порівняння: хмарний
  Regolo відповідає за ~0.65с — `asr.provider: regolo`.
- **Складні назви:** `asr.hotwords` — список термінів («Клод Код», «Пайпер»,
  назви ШІ-моделей), який іде моделі як попередній контекст. Без нього Whisper
  вгадував навмання: «клод-код», «Piper», «коміт-угід». Терміни ЛИШЕ кирилицею:
  заміряно, що латиниця в підказках витягує за собою й сусідні українські слова
  («про це» → «Proceek»). Локально це `hotwords=`, у Regolo — той самий рядок
  як `prompt`.
- **Канонічні назви:** `asr_terms.py` + `asr.aliases` зводять вимови до одного
  написання ПІСЛЯ розпізнавання («джемінай» і «геміні» → `Gemini`, «кван» →
  `Qwen`). Потрібно, бо назви моделей у конфізі латиницею, а короткі назви
  підказки не витягують. Це дзеркало до `voice_latin.py`, який робить
  зворотне перед синтезом; вимову канону там теж прописано.
- **Дві мови:** `asr.languages: [uk, en]`. Одна мова = жорстка фіксація.
  Кілька = мову визначаємо перед розпізнаванням, але ЛИШЕ серед перелічених,
  тому «почулась польська» неможливе за побудовою. Визначає МАЛЕНЬКА модель
  (та сама, що й чорновики): 0.48с при впевненості 0.98, тоді як
  large-v3-turbo дає ту саму відповідь за 2.98с, а `language=None` коштує
  +2.8с. Ціна двох мов — +0.5с на фразу (2.65с → 3.17с); чорновики лишаються
  на першій мові.
- **TTS:** `/api/tts` синтезує українську мову локальним Piper. Це спільний
  голос для віртуального та майбутнього фізичного бота.

### Картинки й довгі репліки на екрані

Бот шукає картинки тулзою `image_search` і вставляє їх у відповідь як
`![підпис](посилання)`. Тайл «Розмова» рендерив цей markdown і раніше (smd),
а от циферблат і «Бот сказав» показували СИРИЙ текст — тобто замість фото
людина бачила дужки з посиланням. Тепер обидва розбирають репліку:

- підпис лишається в тексті замість розмітки (речення читається далі);
- на циферблаті вмикається режим фото (`.tile-face.photo`): **одна рамка на
  майже весь екран, у ній одна картинка**, а в правому нижньому куті сидить
  краб і тримає її за правий кант піднятою клешнею (спрайт `HOLDER_SPRITE` у
  `screen.js`; у маскота з `crab.js` свій автомат станів і пози «тримаю» там
  немає). Клешня одна навмисно — дві симетричні «руки» робили з краба павука.
  Мікрофон на цей час переїжджає ліворуч, щоб не битися з крабом за куток.
  Усе інше на цей час зникає:
  маскот у повний зріст, підпис емоції, субтитр — на 320×240 два центри
  уваги перетворюють екран на кашу;
- кілька картинок гортаються свайпом по рамці, стрілками з боків і показані
  крапками. Свайп гасить спливання події: інакше той самий жест перегорнув
  би ще й карусель тайлів;
- картинка, що не влазить у рамку, лишається ЦІЛОЮ — `object-fit: contain`
  на світлому тлі, тобто з полями. Обрізати фото на 2.4" здебільшого
  означає зробити його невпізнаваним;
- приймаються і зовнішні `https://` (так віддає `image_search`), і шляхи на
  нашому ж сервері — `/uploads/…`, `/file/…`, тобто бот може показати і
  знайдене в мережі, і власний файл;
- вголос розмітка не читається: у Piper іде вже очищений текст.

Заразом прибрано три обрізання, через які довга репліка виглядала обрубаною:
субтитр циферблата різався до останніх 140 символів (тепер текст повний, а
рамка прокручується й тримається довше — пропорційно довжині), SSE-подія
`reply` різалась на 2000 символах (тепер 16000), а вхідне повідомлення чату
довше за 8000 символів відскакувало 422-ю (тепер 32000).

### Стрімінг відповіді

`/api/chat` зі `stream:true` віддає токени як приходять. Але **шлюз OpenClaw
не стрімить**: заміряно — на просту репліку він мовчить 7–30с і повертає всю
відповідь ОДНИМ чанком. Тому чанк довший за 40 символів бекенд вважає
«не стрімінгом» і розсипає на слова (`_LUMP_CHARS` у `main.py`) — текст
зʼявляється на очах, а не стіною. Справжній потік дрібних токенів (Omni,
Anthropic) проходить незайманим.

Сама затримка мозку цим НЕ лікується: 7–30с — це власний агентний цикл
OpenClaw. Для порівняння, ті самі кілька слів через Omni: ~2.2с
(`regolo/gpt-oss-20b`) і ~2.7с (`opencode/muse-spark-1.2-contributor-free`).

### Емоції

Системний промпт просить модель починати відповідь тегом `[емоція:happy]`
(одна з `idle | listening | thinking | speaking | happy | sad | confused |
surprised | love | sleepy`). Бекенд парсить тег і прибирає його з тексту; якщо
тега нема — емоція вгадується евристикою за ключовими словами відповіді.

**Бот міняє емоції й сам.** Фоновий «нагляд за життям» (`vision_watcher`)
публікує емоції через SSE (`/api/events`), тож обличчя оживає без запиту:
- реакція на камеру (коли Vision онлайн): поява людини → `surprised`→`happy`
  + привітання; людина пішла → `sad`; дрімота після 10 хв тиші → `sleepy`;
- **спонтанні емоції у простої**: коли бот спокійний (немає взаємодій
  ≥`mood_calm_s`, не дрімає й не сумує), він зрідка САМ показує випадкову «живу»
  емоцію (`happy/thinking/surprised/love/listening`) на кілька секунд, потім
  повертається в `idle`. Це працює й без Vision. Налаштування — у `config.yaml`
  (`liveliness.mood_*`); `mood_duration_s: 0` повністю вимикає цю поведінку.

### Памʼять

Проста файлова памʼять — markdown-нотатки в `brain/{people,topics,logs}/`.
При кожному чаті топ-3 нотатки за збігом ключових слів запиту підмішуються
в системний промпт. Шляхи нотаток валідуються (захист від path traversal).

| POST | `/api/chat` | `{"message"}` → `{"reply","emotion"}` |

запускали не ми. Логи процесів — у `service_logs/`.

### Окрема консоль (`/console`)

Вікно спостереження, яке тримають збоку під час розмови з ботом: видно не
лише що бот відповів, а через кого це пішло. Відкривається кнопкою
«Окремим вікном» у вкладці «Логи» панелі або прямо за адресою `/console`.

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/console` | Сторінка консолі (процеси + хід розмови + логи) |
| GET | `/api/trace` | `{"turns":[…],"events":[…]}` — історія ходів по кроках |
| GET | `/api/processes` | Стан ланцюга: порт/health/pid + поточний мозок і бекофи |

Хід (turn) — одна репліка користувача. Його кроки пишуть `brains.chat`
(яку модель пробували, скільки тривало, чому впала) і виконання тулзів;
кроки поза ходом (тул від зовнішнього мозку окремим HTTP-запитом, ASR, TTS)
йдуть у власне кільце й показуються в стрічці за часом. Модуль —
`trace_log.py`, огляд процесів — `processes.py`; обидва навмисно не мають
права зламати чат: помилка трасування ковтається.

## Конфігурація

`config.yaml` — порти, шляхи, базові URL і список моделей Omni, **без секретів**.

### Секрети (`.env`)

Секрети живуть лише в оточенні. Найзручніше — у файлі `.env` поряд із `config.yaml`
(формат `KEY=VALUE`, можна в лапках, інлайн-коментар « #...» відрізається); його
читає `app_config` на старті — за будь-якого способу запуску (тому `start.sh`
його НЕ сорсить, лише замикає права `chmod 600`). Реальний `export KEY=...` в
оточенні завжди має пріоритет над `.env`. Тримайте `.env` із правами `600`.

- `OMNI_API_KEY` — ключ Omni-роутера (головний мозок).
- `OPENCLAW_TOKEN` — токен OpenClaw (інакше береться з `../Voice Loop/config.yaml`).
- `ANTHROPIC_API_KEY` — ключ прямого Anthropic API.
- `CHAT2API_API_KEY` — необовʼязковий ключ локального Chat2API.
- `REGOLO_ASR_API_KEY` — ключ Regolo лише для розпізнавання мовлення.

**`.env` — секрет:** не комітьте його, не додавайте у вікі/фронтенд. Ключі
ніколи не повертаються з API і не потрапляють у статику.
