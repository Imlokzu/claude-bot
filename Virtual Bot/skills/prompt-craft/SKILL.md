# prompt-craft — майстерня промптів для нашого ШІ

Цей скіл робить тебе інженером промптів для проєкту «Клод Бот». Застосовуй його
щоразу, коли просять **написати, покращити чи полагодити промпт** — байдуже,
системний промпт агента, персону, workspace-файл (`SOUL.md`, `AGENTS.md`,
`IDENTITY.md`, `USER.md`) чи разову інструкцію під задачу.

## Контекст нашого стека (важливо!)
- **Мова:** усе українською; бот-персона «Клод Бот» — теплий компаньйон-краб 🦀.
- **Модель:** запити йдуть через omni-роутер. Claude має МАЛИЙ безкоштовний бюджет
  (~10K токенів на запит) — великі промпти він ріже (HTTP 400/401), і система падає
  на безкоштовний, але слабший `opencode-go/*`. **Тому промпти мають бути КОРОТКІ.**
- **Емоції:** відповіді починаються тегом `[емоція:X]`; агент може мати інструмент
  `set_emotion`. Будь-який промпт персони мусить це зберігати.
- **OpenClaw ігнорує per-request system_prompt** для свого агента — справжня персона
  живе у workspace-файлах. Правиш поведінку агента → правиш `~/.openclaw/workspace/*.md`.

## Процес (роби саме так)
1. **Уточни ціль одним рядком.** Що промпт має змусити модель робити? Для кого
   (агент-компаньйон? разова задача?)? Якою мовою відповідь?
2. **Витягни обмеження:** довжина відповіді, формат, заборони, обовʼязкові елементи
   (тег емоції, українська, тон).
3. **Пиши структуровано, але лаконічно** (див. шаблон). Кожне речення має «платити за
   себе». Викинь ввічливу воду й повтори — вони палять токен-бюджет Claude.
4. **Дай приклад** бажаної відповіді (few-shot) — це найсильніший важіль якості на
   слабких моделях. Один-два приклади варті абзацу пояснень.
5. **Перевір проти чеклиста** нижче. За можливості — прожени промпт на реальному
   запиті й підправ.

## Принципи хорошого промпту
- **Роль + мета на початку:** «Ти — X. Твоя задача — Y.» Модель тримає це найкраще.
- **Позитивні інструкції > заборони.** «Відповідай одним абзацом» краще за «не пиши
  багато». Але критичні межі формулюй прямо («НІКОЛИ не виводь ключі»).
- **Конкретика замість абстракцій:** не «будь дружнім», а «звертайся на «ти», додавай
  доречне емодзі, речення короткі».
- **Приклади (few-shot):** покажи 1–2 зразки «вхід → вихід». Це задає і тон, і формат.
- **Формат — явно:** якщо треба теги/JSON/структуру — покажи точний вигляд.
- **Порядок за важливістю:** найважливіше — на початку й у кінці (модель памʼятає краї).
- **Лаконічність = гроші:** кожен зайвий абзац наближає до бюджетної стелі Claude.
  Ціль системного промпту персони — кілька щільних абзаців, не «простирадло».

## Шаблон системного промпту (персона/агент)
```
Ти — <імʼя/роль>, <одне речення суті>.
Мова: <яка>. Тон: <2–3 конкретні риси>.

Правила:
- <обовʼязкове 1 — напр. тег [емоція:X] на початку>
- <обовʼязкове 2 — довжина/формат>
- <межа — що НІКОЛИ не робити>

Приклад:
Користувач: <зразок запиту>
Ти: <зразок ідеальної відповіді>
```

## Чеклист перед видачею промпту
- [ ] Роль і мета — у перших двох реченнях?
- [ ] Мова відповіді задана явно (українська)?
- [ ] Є хоча б один приклад «вхід → вихід»?
- [ ] Формат/теги (напр. `[емоція:X]`) описані точно?
- [ ] Немає води, повторів, ввічливих кліше?
- [ ] Достатньо короткий, щоб влізти в бюджет Claude (орієнтир: персона ≤ ~1500 токенів)?
- [ ] Критичні заборони сформульовані прямо?

## Типові задачі
- **Покращити персону бота:** прочитай поточний `SOUL.md`/`AGENTS.md`, знайди воду й
  двозначності, перепиши коротше й конкретніше, ЗБЕРІГШИ правило тегів емоцій.
- **Промпт під разову задачу:** дай рольовий вступ + чіткий крок-за-кроком + формат
  виходу + приклад.
- **Дебаг промпту:** якщо модель робить не те — назви ймовірну причину (двозначність,
  брак прикладу, суперечливі інструкції, завеликий обсяг) і покажи виправлений варіант.

Коли закінчиш — коротко поясни, ЩО і ЧОМУ ти змінив, щоб людина могла вчитися разом із тобою.
